# Project knowledge — phdtv

## Glossary

- **Defense record** — the single schema every sourcing channel (scraper, submission form, curator) emits and edits. Carries provenance (source, last-seen, verified-by) and a status (unverified / published / hidden). Natural key: university + date + normalized candidate name.
- **Sourcing channels** — scraping university agenda pages, submissions from candidates or others, and direct curation. Curation is the review layer that the other two feed, not a parallel source.

- **Field ownership convention** — scrapers may write only the `source` block and fields that are still `null`; once `verified_by` is set they propose via PR but never overwrite curator edits.

- **Disciplines vocabulary** — `disciplines.yaml`, the 42 OECD Frascati minor fields as slugs with major-field parents; the only allowed values for a record's `disciplines`.
- **Recording states** — available (url), none (explicit `recording.status: none`), not-yet-available (no info, ended < 30 days ago), no-recording-known (no info, older).
- **Centerfold** — a magazine-style feature page for one defense at `/centerfold/<id>/`, driven by an optional editorial `centerfold` block on the record (issue, kicker, standfirst, three images, quote, questions, facts). When present it is the page presented for the defense (`Defense.url`); `Defense.listingUrl` keeps the plain page. Empty editorial fields are hidden in production and shown as labelled slots on preview builds (the dev server, or `SITE_PREVIEW=1`).

## Recurring themes

- **TypeScript through and through** (user constraint, 2026-09-03): schema, validator, site build, feeds, tests, future scrapers and submission tooling. No shell logic beyond npm script invocation, no second language. Hugo was rejected on day one for forcing Go templates; Astro was removed on 2026-09-05 in favour of a build script, see `blog/2026-09-05-02-no-astro.md`.
- **React for every UI component** (user constraint, 2026-09-03): anything that renders markup is a React `.tsx`. `src/components/` holds the visible components; `src/site/` holds the document shell, the island helper, the three page functions and the generator. No framework layer.
- **Stack**: React 19 rendered with `react-dom/server` at build time; Vite 8 bundles only the two island entries and the stylesheet (config inline in `src/site/build.ts`, no `vite.config.ts`); Zod schemas; Vitest + React Testing Library under jsdom; Node 24 running TypeScript natively; `tsc --noEmit` as the type check; GitHub Actions for validation and daily Pages deploys; single repository.
- **Pinned versions and why**: js-yaml `4.x` because unquoted timestamps become Dates there, which the schema rejects with the quote hint; the validator and the site build share `parseRecordFile`, so they agree by construction (on 5.x the quoting rule would be moot: an open question). typescript `5.x`.
- **Node strips types but not JSX**: anything `node` runs directly (`scripts/*.ts`, `src/site/build.ts`, `src/site/assets.ts`) must not import a `.tsx` file. The generator is bundled by Vite for the server into `node_modules/.phdtv/site/` and imported from there with a cache-busting query; it must live inside the project so `react-dom` resolves.
- **Child builds spawned from tests must drop `NODE_ENV`** (Vitest sets `test`), or Vite bundles React's development build; see `test/build/bundle.test.ts`.
- **React 19 `renderToString` emits no doctype** for an `<html>` root; `renderDocument` in `src/site/pages.tsx` adds it.
- **Deploy key is rrsync-restricted**: `/home/phdtv/.ssh/authorized_keys` carries `command="/usr/bin/rrsync /home/phdtv/site",restrict`, so the key can only rsync into that directory; rotating it means editing that file and the `DEPLOY_SSH_KEY` secret together. Apple's `openrsync` on the Mac cannot talk to rrsync (and lacks `--chmod`); test uploads from a Linux rsync (a Docker alpine container works).
- **nginx on the VPS has no `.ics` MIME mapping**; the phdtv vhost re-includes `mime.types` and adds `text/calendar ics` itself. `charset_types` must not list `text/html` (already default; nginx warns).
- **Squarespace's domain panel** never reaches the Chrome extension's `document_idle`, so screenshots and the accessibility tree time out there; `javascript_tool` works, one short synchronous script per step (long awaited scripts hit the 45 s evaluate timeout). Editing DNS demands a password re-authentication that the user must type; it expires within minutes.
- **Claude Design (claude.ai/design) from the Chrome extension**: the page never reaches `document_idle`, so screenshots, `read_page` and `get_page_text` time out; `javascript_tool` works. Extension clicks land on top-level triggers (the design-system button, Create) but items inside popovers ignore them: dispatch a pointerdown/mousedown/pointerup/mouseup/click sequence on the element from JS instead. The prompt box is a contenteditable; `document.execCommand('insertText')` after `focus()` fills it and enables Create. The org-default design system is preselected; the "Clear selection" button in the picker sets it to None. Preview iframes are on `<project>.claudeusercontent.com` with token query strings the extension redacts, so the built page can only be seen by downloading it (page menu → More actions → Download). The download is Claude Design's `.dc.html` template format (`sc-if`, `sc-for`, `{{ }}`, a `DCLogic` class), not runnable HTML; `blog/media/2026-09-06-01-calendar-views-designed/build-runtime.js` renders it standalone, and headless Chrome (`--headless=new --screenshot`) captures it. Headless Chrome clamps windows to about 500px wide, so test phone widths inside an iframe.
- **Record timestamps must be quoted** in YAML; the schema rejects Date objects with a hint. Offsets must match the zone at that instant.
- **Dates in the calendar are `YYYY-MM-DD` strings**, never `Date` objects: `src/lib/calendar.ts` parses, adds and reformats them, so the grid code has no DST edge cases. The only zone-aware step is `localDateString` (an `Intl.DateTimeFormat('en-CA')` call); the build groups with a null zone (institution-local, matching the record filename), the browser regroups in the viewer's zone after hydration.
- **Intl locale quirks**: `en-GB` writes "Sept" and lacks "EDT"; `en-US` lacks "CEST". `src/lib/time.ts` assembles dates from parts and tries both locales for abbreviations.
- **Real-world stream links**: Utrecht uses one shared Senate Hall livestream URL for every defense; Twente and Wageningen use one shared YuJa page; VU streams to a YouTube channel; Erasmus gives the link only to the candidate; UvA keeps videos one month, UEF deletes within ten days unless asked.

- **Shell gotcha:** the user's zsh profile defines `node`/`npm` as nvm lazy-load wrapper functions that call `_nvm_lazy_load`. In non-interactive Claude Code shells that function is undefined, so `node`/`npm` recurse until `FUNCNEST` is hit. Call binaries by full path (`/opt/homebrew/bin/node`, `/opt/homebrew/bin/npm`, `/opt/homebrew/bin/openspec`) instead.
- **`npm run dev` serves its own checkout only**: `scripts/dev.ts` builds that checkout's `dist/` and watches that checkout's `src/`, `records/`, `universities/`. With work spread over `.claude/worktrees/*`, a server started in the primary checkout shows `main`, never a worktree's changes; run one per worktree with a distinct `PORT` (the port is strict, so a second server on 4321 fails to start).
- **Claude Code worktree sessions have a Bash guard** that refuses heredocs, `env` prefixes, quoted command paths, `git -C <other worktree>` and other "complex" commands as unverifiable git operations. Use the Write and Edit tools for file contents and a short wrapper script with a plain name for commands with awkward paths such as headless Chrome (a symlink breaks Chrome, which resolves its framework from the executable's path).
- **Island-scoped stylesheets**: a client entry that imports a `.css` file gets it listed under `css` in its Vite manifest entry, and `pageAssets` already adds those to the page, so a page-specific stylesheet costs one import and no change to `global.css` (see `src/site/client/centerfold.tsx`).
- **Parallel sessions on one repository** (2026-09-06): the `calendar-views`, `centerfold` and about-page branches were built at the same time in sibling worktrees under `.claude/worktrees/` by Claude Code sessions that coordinated by cross-session message. The rule that worked: one branch owns the shared styling layer (`global.css`, `Shell.tsx`, `PageIntro.tsx`, the headline strip, the font packages); a feature branch owns only its own files, uses the shared token and class names, and rebases when told. Never write into another session's worktree; message it. Integration was two merge commits into `main` (calendar first, then centerfold), the repository's first, because replaying seventeen commits through the same about-page conflicts made no sense; parallel sessions also number the day's devlog entries independently, so renumber by timestamp at merge time.
- **React's server renderer puts `<!-- -->` between adjacent text nodes**, so a label assembled from several JSX text pieces never matches a plain string in the HTML; build it as one template string when a test or a scraper reads the output.
- **Component tests that hydrate a viewer clock** must pin `process.env.TZ` (Node honours the change at runtime) and fake `Date` with `vi.useFakeTimers({ toFake: ['Date'] })`; otherwise the after-mount render follows the machine's zone and the real date, and a fixture in the past turns upcoming.
- **Two clocks in the stories**: components that take `now` as a prop get `PINNED_NOW` and a fixed viewer zone, so their stories never drift; components that read the viewer clock after mount (`DefensePage`, `DefenseCalendar`, `CenterfoldPage`) get defenses placed relative to `new Date()` at module load, so their live stories are live when opened and go stale after an hour or so (a reload resets them). `DefenseCalendar` writes its view and filters into the preview iframe's URL with `replaceState`, which strips Storybook's own query; switching stories still works, only a hard reload of the bare iframe loses its place.
- **Headless Chrome against a static Storybook**: serve `storybook-static/` (`python3 -m http.server`), shoot `iframe.html?id=<story-id>&viewMode=story` with `--screenshot`; each instance takes about 30 s and lingers, so `pkill -f headless=new` afterwards. More than about three instances at once against that server produces Storybook's error page ("Failed to fetch dynamically imported module") instead of the story, and the PNG looks plausible by size, so check the images.
