## What changed

A second user constraint landed after the [first change was drafted](2026-09-03-04-first-change-scaffolded.md): **React for any UI components**. The design and task list of `record-format-and-site` were updated to make it binding. Specs did not change, since they describe behaviour and never named a framework. The change still passes `openspec validate --strict`.

## Why it matters

"TypeScript through and through" plus "React for all UI" narrows the site stack to one honest shape. The obvious alternative, Next.js with static export, is React end to end but has no equivalent of typed content collections, so the schema-at-build guarantee would have to be hand-rolled. Astro with its React integration keeps that guarantee and lets React own everything visible.

## How it works

The division of labour is now strict:

```
  src/pages/        Astro: routing, loading collections, .ics and .json
                    endpoints, the HTML document shell. Each page is a
                    data-loading header plus one <Page {...props} />.

  src/components/   React .tsx: layout chrome, defense card, day-grouped
                    lists, detail body, filters, the schedule island.
                    Static ones render to HTML at build and ship no JS;
                    the ones that need the viewer clock get client:load.
```

The nicest consequence is in the time handling. The `DefenseSchedule` component renders institution-local times at build time, which is the no-script fallback. Hydrated in the browser, the same component reads the viewer's clock and zone in an effect and re-renders with viewer-local times and recomputed upcoming and live membership. One component, two states, instead of a server template plus a separate script rewriting its output. Hydration mismatch is avoided by rendering the build-time view on the first client render and switching in an effect.

Testing follows: React Testing Library under jsdom for components, asserting on text and roles rather than markup, alongside the existing Vitest coverage for schema, validator, time helpers and the iCalendar serialiser.
